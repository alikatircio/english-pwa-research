# Batch C verification report

Independent verifier, 2026-10-22. Input: `batch-c.json` (not modified). Output: `batch-c.verified.json` (36 items, all kept).

**Result: 36 verified, 0 unsure, 0 rejected.** 3 commonMistakes were removed, 2 checklist/note statements that called correct English wrong were fixed, and 1 situationTr giveaway and 1 situationTr addressee error were fixed.

## Sources and tools
- Dictionaries fetched with curl (all returned content): Cambridge, Oxford Learner's, Longman (LDOCE). Patterns were checked by grepping the page text, not taken from the author's notes.
- SkELL API: run for every targetChunk and every commonMistake. **Caveat:** SkELL matches lemmas ("in term of" also returns "in terms of", and "in charge for" also returns "in charging for"), so it cannot test singular/plural or inflection mistakes. For those, Google Books Ngram (en-2019, 2010-2019 mean, exact form) was used.
- Benchmark for "clearly wrong": the Longman-flagged error *discuss about* runs at 0.9% of *discuss the* in Ngram. Mistakes at or below that rate, with no native line in SkELL in the target sense, count as clearly wrong.
- Web search for domain usage (git/GitHub, test-environment docs) and for learner-error evidence (overpassivization in Turkish EFL learners: Tanyer & Deniz 2022; the 'kontrol etmek'/check overlap: WordReference).
- The real `scripts/build-content.ts` was run on a temp copy (`--drafts/--out/--lock` all in the scratchpad) with batch A + B + C verified files: `content:build ok: 103 verified item(s)`, no errors, and no batch C warnings. `src/content/items.json` and `content/shipped-ids.lock.json` were never written (git diff empty).

| *should have test*, *Is the test pass*, *are pass*, *some clarify* | **kept** | Base form after perfect *have*, and *be* + base verb (04 §1.1c), are ungrammatical. *some clarify* is verb-for-noun (04 §1.3a), and SkELL has only *clarified/clarifying* there. |
| *revert back* | **removed** | Ngram *revert back* is 5x *revert the*. SkELL has 645 hits. Brians' *Common Errors* calls it only "a pointless redundancy", i.e. style. Checklist and note now present it as a style tip, not an error. |
| *merge to main* | **kept as accepted** | Real docs use it (bec.readthedocs.io "merge changes to main", AllSpice "merge a local branch to main"), and SkELL has *Merged to master* lines. Oxford and GitHub Docs give *into* (canonical). |
| 6 empty commonMistakes | **left empty** | No evidence of a typical error for prioritise, catch-up-on, run-tests-against-staging, merge-pr-into-main, take-over-from or mention. The field is optional (04 §5/13). Nothing was invented. |
| *has failed since* | **not added** | 04 §2.2/2 accepts only the target pattern. noteTr already mentions it. |

- Schema: the author wrote `commonMistake: null` (the schema says optional string). The build tolerates it, but the keys are now removed.
- Not changed (accepted convention from 04 §2.1/1 and batches A/B): the channel tags *[Teams]* and *[Jira yorumu]*. They are product names but are the spec's own channel labels.
